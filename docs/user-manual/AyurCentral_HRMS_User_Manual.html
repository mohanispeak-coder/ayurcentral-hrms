1. Introduction

Dashboard (Main → Dashboard)

The dashboard is the home page after sign-in. It shows counts and shortcuts based on your role (for example leave approvals for managers, payroll status for HR, your employee ID for staff). Use the sidebar to go to detailed screens.

AyurCentral HRMS is a browser-based Human Resource Management System. Your company uses it to keep employee records, process leave, record attendance, run payroll, and manage hiring.

This manual is written in simple English. It was built by reading your actual Apps Script project export, so it matches the screens and labels in your deployed app.

What you need

  • A computer or phone with a modern browser (Chrome recommended).
  • Your company Google account (work email).
  • The HRMS web app URL from IT or HR (usually ends with /exec).

2. Sign in and daily use

2.1 First visit

  1. Open the HRMS link in your browser.
  2. Choose your Google work account when Google asks you to sign in.
  3. Wait for the dashboard to load. The left side shows the menu.
  4. If you see an error about access, your login is not set up yet. Contact Admin or HR.

2.2 Parts of the screen

  • Sidebar (left): Sections such as Main, My Work, People, Time Off, Attendance, Payroll, Recruitment, System. Click a section name to expand or collapse it.
  • Top bar: Page title, notification bell, your name and role, Sign out.
  • Main page: Forms, tables, and buttons for the task you selected.
  • Refresh: Many pages have a refresh control to reload data from the server.
  • Ask HR: Floating help button to ask HR questions (when enabled).

2.3 Sign out

Always click Sign out when you finish on a shared computer.

2.4 After an app update

Press Ctrl+Shift+R (Windows) or Cmd+Shift+R (Mac) once to hard refresh if menus or buttons look old.

3. Roles and access

Each user has a role. The role controls which menu items appear.

RoleTypical access
EMPLOYEEDashboard; My Work (profile, leave, payslips if enabled). Cannot open company employee list or payroll admin.
MANAGEREverything Employee has, plus My Team and Leave Approvals. May see Recruitment if Admin allows.
HRPeople, leave admin, attendance, payroll, recruitment, notifications, settings (no full owner powers).
ADMINSame as HR plus full settings; Users screen may show 'coming soon' in this build.
OWNERFull access to all modules. Module checkboxes in Settings do not limit OWNER.
Admin can change which modules each role sees under System → Settings → HRMS module access by role. If a menu is missing, ask Admin before reporting a bug.

6. HR: Employee records

Open People → Employees. You can search by employee ID or name and filter by status, department, location, and vertical.

Buttons on the Employees page

  • Mandatory fields - open the checklist of required fields (if present in your build).
  • Custom fields - define extra columns for profiles and bulk upload.
  • Bulk upload - import many employees from Excel or CSV.
  • Add employee - create one employee.
  • Refresh - reload the directory list.

6.1 Add one employee

  1. Click Add employee.
  2. Fill every field that has a red star (*). Stars follow your Mandatory fields settings.
  3. Employee code must match your format (for example SAPL-0001, AOPL-0001, AOMS-0001).
  4. Employment type is usually one of: PERMANENT, CONTRACT, INTERN, CONSULTANT.
  5. Choose the correct vertical for the employee.
  6. Bank: if you enter account number, IFSC is usually required (unless Mandatory fields say otherwise).
  7. Click save. Fix any red error messages and try again.

6.2 Employee profile

Click a row in the directory to open the profile. Your build includes these areas:

  • Personal - edit or view details in this section (HR permissions apply).
  • Employment - edit or view details in this section (HR permissions apply).
  • Payroll - edit or view details in this section (HR permissions apply).
  • Documents - edit or view details in this section (HR permissions apply).
  • Payslips - edit or view details in this section (HR permissions apply).
  • Access - edit or view details in this section (HR permissions apply).

HR can upload documents, change status (active/inactive), send welcome email, and manage app login access from the profile where those buttons appear.

6.3 Bulk upload

  1. From Employees, open Bulk upload.
  2. Download the template (new hire or legacy/existing employee variant).
  3. Fill one row per employee. Do not rename header columns.
  4. Upload the file. Wait for validation.
  5. Review errors per row. Fix the file and re-upload if needed.
  6. Confirm import only when all rows you need are valid.

Rules printed in your template

  • After upload, review validation results before confirming import.
  • Legacy / existing employees - set create_login to NO unless issuing portal access now.
  • New hires - use create_login YES when creating Google sign-in.
  • Required columns are marked with * in the Employees sheet header row.
  • Employee code format: SAPL-0001, AOPL-0001, AOMS-0001 (provided by HR, not auto-generated).
  • Dates must be YYYY-MM-DD.
  • create_login: YES or NO. If YES, google_login_email is required.
  • System role is always EMPLOYEE on create. Admin assigns HR/Manager/Admin separately.
  • manager_employee_id must already exist in HRMS (e.g. SAPL-0005).
  • Do not change header names on the Employees sheet.
Maximum rows per upload is limited in software (commonly 100). Split large files if needed.

6.4 Mandatory fields

Path: People → Mandatory fields or the button on Employees.

  1. Review fields grouped by Identity, Contact, Work, Payroll, Bank, etc.
  2. Tick Mandatory for fields that must be filled on create and bulk upload.
  3. Employee code cannot be turned off.
  4. Click Save. The page reloads so forms and templates match.

After save, single employee forms show red stars on required fields. Bulk templates mark required columns with * in the header row.

6.5 Custom fields

  1. Open Custom fields from Employees.
  2. Enter field key (lowercase, underscores, e.g. blood_group) and label.
  3. Mark Active if the field should appear on forms and bulk template.
  4. Save. New columns appear on bulk upload after save.

7. HR: Leave

7.1 Leave administration (Time Off → Leave)

Company leave requests and configurable leave types.

HR uses this area to:

  • Configure leave types (annual, sick, etc. as your company set up).
  • View and manage employee leave requests and balances.
  • Support corrections according to company policy.

7.2 Leave approvals (Time Off → Leave Approvals)

Submitted requests waiting for a decision.

  1. Open Leave Approvals.
  2. Select a pending request.
  3. Approve or reject. Add a comment if your process requires it.
  4. Employee and manager may receive email if toggles are on in Settings.

7.3 Employee leave apply (for reference)

Employees use My Leave → Apply. Dates are counted on the server. Half-day is 0.5 when the type allows it.

8. HR: Attendance

8.1 Register (Attendance → Register)

Monthly attendance register (Form XVII style): daily codes, summaries, and payroll day counts.

  1. Select payroll month and vertical if the screen asks.
  2. Download the attendance template.
  3. Enter one attendance code per day for each employee.
  4. Upload the file and review validation messages.
  5. Confirm when data is correct.

8.2 Form T (Attendance → Form T)

Statutory Form T Excel export per vertical for the selected payroll month.

Choose payroll period and vertical, then generate or download the Form T Excel export as per your statutory process.

9. HR: Payroll and salary

9.1 Salary structure

Create reusable salary structure templates (vertical + component percentages) and assign them to employees.

Create templates with earning/deduction components. Assign a structure and monthly CTC on the employee profile for payroll to work.

9.2 Salary Statement

Monthly cost-to-company breakdown by employee from structure templates and CTC.

9.3 Payroll run (Payroll → Payroll)

One primary next step. Locked amounts never change.

Typical monthly flow:

  1. Open the payroll month you need.
  2. Sync or load employees for that run.
  3. Enter or import attendance / LOP adjustments if your process uses them.
  4. Save inputs.
  5. Calculate payroll and review amounts.
  6. Fix errors (missing bank, structure, etc.) before finalize.
  7. Finalize or lock the run when numbers are approved.
  8. Generate payslips. Employees see them under My Payslips when enabled.
Locked payroll amounts do not change. Use correction run features in the app if your build includes them.

10. HR: Recruitment (ATS)

Menus: Recruitment, Jobs, Candidates.

  • Jobs - Create, publish, and share requisitions.
  • Candidates - Applicants for jobs you can access.
  • Job detail pages support pipeline stages, interviews, and public apply links.
  • Hired candidates are not automatic employees; create them in Employees when they join.

11. Manager tasks

  • My Team - Direct reports. Open a row to view work details.
  • Leave Approvals - act on team leave requests promptly.
  • My Leave / My Profile / My Payslips - same as any employee.
  • Recruitment screens if Admin enabled Manager access.
